## 后续独立批次

1. 410 个 operation 已全部由实际 `OpenApiRouter` 注册；后续维护仅可在新增动态 JSON 处理器时补充兼容 schema，生成器继续以 410 个全类型 operation、零领域回退为硬门禁。

3. 配置/元数据、系统事件、通知 Provider/Rule/触发/投递历史以及白名单记录/地域文档均以类型表主读，并与旧 keyspace 比较；mobility/TTL aggregate、普通认证登录退避、Docker 管理会话/退避、子域规则签发限流与持久 grant/index、WOL 唤醒冷却、Passkey 短期能力、OIDC/LDAP、fnOS Share、HMAC nonce、白名单 owner/lock 及通知运行时完整单元已完成整体类型表、同事务双写和 legacy-primary shadow compare。下一小版本在积累无差异运行证据后才允许切换比较式 typed 主读。2.x 保留 Redis 导入和 backup schema v1，3.0 前不删除兼容层。

安全敏感 keyspace 审计已完成：所有直接参与认证、授权、限流、退避、唯一消费、白名单所有权或精确失效的兼容状态均已按完整聚合建立 typed shadow；shadow 数据不得参与授权、放宽限流、延长会话或提前消费任务。`recent_auth_ips` 只用于扫描降噪和公共地点统计，expired-session cleanup marker 只在权威会话已删除后去重清理，ACME/DDNS/更新/监控锁只协调运维任务，终端状态由显式会话管理器持有，均不属于认证 authority。所有保守 shadow 切换主读前仍必须积累受保护诊断的无差异运行证据；这是下一版本的发布证据门，不通过在当前版本伪造运行时数据来提前切换。

会话审计结论：普通认证、Docker 管理与 IP mobility 会话记录本身均是认证 TTL 的安全边界。Docker 管理会话已连同 XX 刷新、撤销和登录退避整体进入 legacy-primary shadow；普通认证会话已纳入完整 mobility aggregate，授权读取定向比较 shadow，撤销则原子删除 session authority 与内部 mobility 状态。两类会话都禁止 typed-only 数据参与授权，需积累无差异证据后才允许切换主读。

会话迁移不变量：IP mobility 必须作为一个完整 aggregate 迁移，包含认证会话、subject binding、session binding index、timeline、summary、active-IP zset/details、pending whitelist、whitelist owner 与 mutation lock。类型化读路径只有在同一 SQLite `IMMEDIATE` 事务中保持这些记录的到期、撤销、所有权和索引一致，并针对现有 EVAL 路径完成 shadow compare、断电、并发写、旧版回滚及 backup schema v1 导入测试后才能启用。

白名单审计结论：记录与地域文档已经在不改变授权结果的前提下切换为比较式类型主读；关键更新仍以当前记录 JSON 为比较值执行条件 pipeline，保证自动授权和过期清理不会覆盖并发修改。会话 binding、pending index、owner 和 mutation lock 保持在完整 mobility aggregate；独立的自动白名单 owner→record sidecar 及其租约锁则作为 `whitelist_auto_owner_*` 完整单元同事务 shadow，不再存在未覆盖的白名单所有权键。
4. Rust/Go/Vue 热点拆分、前端目标预算、Go hot benchmark 以及 Rust/Go RSS/readiness p95 同机比较门禁均已落地。仅“是否增加额外 SQLite 只读连接”保持条件性决策：只有真实 32 并发基准证明 p95 至少改善 25% 时才允许启用；当前未增加连接池不是未完成实现。
