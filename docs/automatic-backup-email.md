# 自动备份邮件

在系统设置的自动备份区域配置 SMTP、发件人和收件人，然后启用邮件邮寄并保存。邮件配置独立于通知中心；“发送测试邮件”使用当前表单与已保存密码，发送小型测试附件，不保存表单，也不生成备份。

备份仍按原有周期写入本地目录，成功落盘并提交运行状态后，独立 worker 邮寄相同的 `.knock` 文件。邮件显示实例名称、备份时间、文件名和大小。界面分别显示本地备份与邮寄结果。

- 邮寄默认关闭；默认端口 465、TLS、超时 30 秒、附件上限 20 MiB。
- 附件上限可设为 1–100 MiB，按原始文件大小判断。SMTP 服务商仍可能因编码后的邮件大小或自身策略拒收。
- 附件超限时尝试发送不含附件的说明邮件，附件邮寄仍记为失败，文件保留在本地。
- 临时错误在 1、5、30 分钟后重试，共最多 4 次尝试。认证或其他永久拒收、无效地址、文件缺失和附件超限不重试。
- 待发任务最多保留 24 小时，其附件暂缓过期清理。关闭自动备份或邮寄、修改邮件配置会取消未开始的旧任务；已经提交给 SMTP 的邮件不能撤回。
- 重启会恢复未完成任务。进程存活时，已知 SMTP 结果会保留到状态写入成功，存储暂时失败不会触发重发。SMTP 接收成功与本地成功记录之间发生进程中断时，仍可能再次发送相同 Message-ID 的邮件。

## 封装与数据

`infra::mail` 负责 SMTP、TLS、MIME 和不包含凭据的错误分类；通知与备份分别适配该基础设施。`infra::credentials` 为现有面板同步与备份提供独立命名空间的本机加密存储，保持原面板同步凭据格式兼容。

自动备份分为配置、归档存储、调度与 `backup_email` 邮寄策略。备份运行状态与待发任务通过同一原子操作提交。worker 在维护锁内认领任务和保存结果，在锁外读取附件、请求 SMTP；任务中的文件名只允许指向自动备份目录内的归档，读取时禁止跟随符号链接。

邮寄状态存于 `fn_knock:config:backup:automatic:email`。任务不包含密码或附件副本。SMTP 密码以版本化加密凭据保存在数据目录的 `backup-email` 子目录；先写入新凭据，提交配置成功后删除旧凭据，提交失败则丢弃新凭据。

邮件配置、凭据和任务不导出到备份。恢复备份保留目标机器现有邮件配置及运行状态，不导入历史任务；新机器需要重新配置邮件。清空全部数据会清理邮件凭据。

## API

- `GET /api/admin/maintenance/backup/automatic`：`config.email` 为公开配置，`status.email` 为独立邮寄状态。
- `PUT /api/admin/maintenance/backup/automatic`：可选 `email` 字段；省略整个字段时保留邮件配置。`email.password` 仅写入，省略或空字符串保留已存密码；`clear_password: true` 显式清除。查询仅返回 `password_configured`。
- `POST /api/admin/maintenance/backup/automatic/email/test`：接收与 `email` 相同的配置，使用草稿发送测试邮件。沿用管理员鉴权。

完整类型见生成的 OpenAPI 契约。测试使用本机临时 SMTP 服务，无需外部邮箱。
