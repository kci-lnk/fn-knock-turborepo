# 预期停机与运行健康告警修复

2026-09-10：设计已审计，FPK 完整版实现已落地，尚未部署设备。其他平台保留原行为，需要各自接入和验收。

## 故障与修复范围

事件 `evt_dc86e94780424139af8ffdff` 的北京时间线：07:40:13 收到停止请求，14 秒网关开始正常退出，15/20/25 秒管理端探测失败，25 秒生成错误事件，29 秒网关和管理端正常退出，51–52 秒新版本启动。

修复保留“先网关、后管理端”的安全退出顺序，管理端在网关 draining 时仍提供认证服务。正常停机不再触发新的网关健康失败、依赖 blocked 或虚假 recovered。07:39:52–07:40:10 的 SQLite 失败发生在停机之前，不能追溯消除，也不属于此次抑制范围。

## 审计结论

原设计需要修正或明确的地方：

1. 不能直接读取历史 `stop_requested` 就开始静默。现有 supervisor hints 是一次性历史消息，有七天保留期，且当前消费者只处理异常退出。
2. 仅增加 TTL 不足以避免 PID 复用、跨系统启动残留或探测并发。必须绑定实例，确认状态已生效后才发 TERM。
3. 不能依赖 SQLite 或网关 RPC 完成停止确认，它们可能正是异常组件。
4. 暂停所有探测会隐藏 storage 故障；把状态改成 healthy 或直接清除 incident 会产生错误恢复记录。
5. 停止请求不等于授权未来任意重启。启动预期必须另外绑定实际启动的进程。
6. 不能把“准备发送 KILL”写成已观察到的退出码 137；现在单独记录超时错误和发送信号事实，未知退出码保持 null。
7. 强制 ACK 协议不能阻止从旧版本升级。旧管理端无协议时允许明确记录的兼容路径，但不承诺旧监控零误报。

## 停止协议

运行目录 `runtime/planned-stop/` 保存固定文件，权限为目录 0700、文件 0600：

- `manager`：管理端 PID、/proc starttime、实例 ID、boot ID，表示当前管理端支持协议。
- `instance`：协议版本、管理端 PID/实例/starttime、网关 PID/实例/starttime、boot ID。
- `request.json`：版本、operation ID、两个目标实例、action、请求时间及有限超时。
- `ack`：operation ID、管理端实例、网关实例。

文件通过临时文件加 rename 发布，解析内容而不执行 shell source。单次请求不超过 4 KiB。

FPK start/stop 通过 `flock -o` 串行化。锁不继承给长期运行的子进程；内部清理可调用 stop 函数，无需递归加锁。锁等待有界，并在启动子服务前清除内部重入环境标志。

停止流程：

1. 完成可能拒绝停止的 WAF 前置检查。
2. 核对 PID 文件、实例描述、boot ID 和进程 starttime。
3. 生成唯一 operation ID，原子写入 `prepare`。
4. 独立控制任务每 100 ms 检查请求，不等待 RPC 或数据库发布；验证目标实例、参数及请求新鲜度后提交 stopping。
5. 管理端写 ACK。启动器最多等待 3 秒，再次检查身份，只有精确匹配 ACK 才发 TERM。
6. 网关退出后写 `gateway_stopped`，再关闭管理端。正常结束写 supervisor `stop_completed`；失败路径写 `stop_failed` 或 `stop_canceled`。

已支持协议但无法确认的管理端会使普通停止明确失败，进程保持运行。旧版本无有效支持描述时走 legacy 路径并写日志。该兼容路径不会主动标记任何进程为预期停机。

## 并发、期限和退出

生命周期状态和健康 tracker 提交使用同一短临界区，不在状态锁内执行数据库、网络或文件等待。每轮探测记录 generation：停止生效前已提交的事件保留；跨越停止/取消边界的在途结果不生成新的事件。取消之后新探测继续使用原有失败阈值。取消或到期后，旧的 healthy 快照不能直接恢复 readiness；必须等待当前 generation 的新探测提交。

受控组件仅为 gateway_process、gateway_dataplane、auth_bridge、config_sync。storage 和 management 不受网关停止状态屏蔽。停止前的 incident 不清除，成功探测在停止窗口内也不生成 recovered。

启动器继续执行逐进程优雅退出期限与强制退出期限。管理端的总保护期限为 `2 × (STOP_TIMEOUT_SECONDS + FORCE_KILL_TIMEOUT_SECONDS) + 10` 秒，默认 180 秒，最大 3600 秒。该总期限是启动器崩溃时的兜底，不替代每个进程的超时。重复 prepare 不续租。

- cancel：解除抑制，唤醒探测；同一请求不可重新激活。
- 期限到达：单调时钟解除抑制，唤醒探测，持久化 stop_failed 提示。
- TERM 失败：记录 stop_signal_failed，解除预期停机。
- 优雅退出超时：记录 stop_timeout 错误；成功发送 KILL 后单独记录 signal_sent，退出码未知仍为 null。
- 收到新的网关实例：解除旧操作，记录 gateway_replaced_during_stop；新实例不继承静默状态。
- 异常退出提示：保持独立导入，即使正在预期停机也不被屏蔽。

进程 starttime 对同一实例只绑定一次，不能在旧 PID 被复用后重新读取新进程 starttime 并更新旧描述。

## 快照、页面和事件

组件及顶层快照增加可选 lifecycle。没有字段表示普通运行；phase 为 stopping 或 stopped。保留最后有效健康状态，但 readiness 在预期停机时返回不可就绪。顶层不能继续给出 healthy；页面显示“正在停止”，同时保留已有异常提示。

新增 `FN_EVENT_RUNTIME_STOP_FAILED`，接入事件中心、通知类型、模板、OpenAPI、生成契约及五种语言。停止失败日志包含 operation ID，方便关联启动器和管理端记录。诊断快照及原有 supervisor/management 日志共同保存活动状态和历史结果。

FPK 启动器为管理端提供启动时网关 PID/starttime。仅首次观察到这一确切进程时，将对应启动/重启记录为 INFO/platform_start；后续未匹配的实例变化仍为 WARN/instance_changed。单独一条历史 stop 记录不会降低未来重启的级别。

## 回归与发布边界

验证覆盖：

- 本次连续三次失败期间无网关错误，storage 仍能生成错误。
- 未提供停止请求时，仍按三次失败阈值告警。
- 停机前已有 incident 不被清除，异常退出和停止失败事件正常导入。
- 旧 ACK、错误实例、错误 operation ID、过期请求及重复请求无法错误授权或续期。
- 取消后在途结果丢弃，新探测恢复判断；实例被替换后解除旧操作。
- 页面显示停止状态、保留已有异常、兼容旧快照。
- Shell 确认、取消、旧版本兼容和先网关后管理端的实际函数顺序。

测试不需要停止正在使用的应用。设备打包升级演练尚未执行，发布前应在测试设备验证一次完整启停和升级。首次从旧版本升级时，旧进程不具备修复，可能仍产生最后一次旧逻辑告警。

本次未把强制关机路径包装成无告警的预期停机，也没有解决 SQLite 变慢的独立原因。跨平台启动器适配和完整进程崩溃取证仍按各平台已有能力处理，不能把缺少异常退出证据解释为没有异常退出。
