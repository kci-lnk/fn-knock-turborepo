# WAF 违规频次自动加黑

WAF 设置中的“违规频次自动加黑”默认关闭。开启后，仅 WAF 实际拦截的请求消耗令牌：同一 IP 跨站点共享一个桶，一个请求命中多条规则仍只消耗一个令牌。正常请求、检测模式、仅记录的命中、内部处理错误和被现有 WAF 豁免规则放行的请求不累计。

| 配置字段 | 默认值 | 范围 |
| --- | --- | --- |
| `violation_rate_limit_enabled` | `false` | 布尔值 |
| `violation_rate_limit_capacity` | `5` | 整数 1–10000 |
| `violation_rate_limit_refill_seconds` | `60` | 整数 1–86400 秒 |

初始桶满，每经过指定秒数补充一个令牌，连续补充且不超过桶容量。默认情况下，没有令牌补充时，第 6 次违规会自动加入通用黑名单。这不是固定时间窗口内的计数器。

当次请求沿用 WAF 的错误页或断开连接行为；后续请求按照通用黑名单原有规则处理。黑名单来源显示为“WAF 违规频次”，备注保存触发时的桶参数和请求 Trace ID。网关日志记录自动加黑成功或失败。

黑名单持久保存，关闭功能、关闭 WAF 或重启网关不会自动解封。手动移除黑名单后，该 IP 的额度重新从满桶开始。令牌桶本身仅保存在单个网关进程内；修改开关或桶参数、重启网关会清空桶，普通 WAF 规则更新保留桶。解封或阈值变更前已开始 WAF 检查的请求，不会在检查完成后消耗重置后的额度。

自动加黑沿用黑名单配置持久化事务，失败时保留原有 WAF 拦截，并在该 IP 后续违规请求到达时重试，两次尝试至少间隔 5 秒。同一 IP 的并发触发不会重复添加或覆盖已有记录的来源和备注。

桶最多保留 100000 个。违规流量到达时，每分钟最多清理一次已恢复满额的闲置桶；达到容量上限时淘汰最久未访问的桶并记录告警，不因容量压力直接加黑。

频次参数使用独立草稿，刷新其他 WAF 设置不会覆盖未保存的参数；关闭功能时沿用已保存的合法阈值，未完成的参数输入不会阻止关闭。WAF 配置更新与规则修改串行执行，保存前完成详情读取，避免详情读取失败被误报为已经生效的配置保存失败。

该功能使用控制 API 版本 26，需要配套更新管理端和 Go 网关。旧配置缺失新字段时采用上述默认值。
