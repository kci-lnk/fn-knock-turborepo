# 请求日志容量限制

系统设置 → 请求日志支持配置每日容量、总容量和保留天数。默认每日 256 MiB、总计 1024 MiB，1 MiB = 1,048,576 字节。容量输入为 1–1,048,576 的整数，总容量不能小于每日容量。不提供无限制选项。

任一上限触发即从最旧日志开始清理，继续记录最新请求；调低额度、启动或切换目录后执行清理。清理以分片为单位，实际保留量可能略低于额度。日志查询和请求统计仅覆盖保留的数据，不能作为完整流量计量。已清理记录不可恢复，即使配置保存失败后回滚也无法恢复日志。

新日志使用 `YYYY-MM-DD.<序号>.log`，单片最多 16 MiB；较小额度会缩小分片。写入缓冲区也计入容量。单条记录不得超过分片容量或读取器的 8 MiB 单条上限，超出时丢弃该条记录。轮转、删除和统计均识别旧的 `YYYY-MM-DD.log`。单个旧文件超限时，保留最新一个分片容量内的完整记录；整理临时文件不超过一个分片大小，不会把整个旧文件读入内存。整理失败保留源文件内容并停止增长，页面显示错误；源文件可能已换为新的分片名，以确保旧游标不会指向替换后的字节。整理会保留原文件权限。修复存储问题后，未写完的缓冲数据会继续刷盘，后续写入重试清理。

容量只计算当前目录下受管理的请求日志文件及缓冲数据；不包括运行日志、独立 WAF 日志、文件系统元数据或用户自行放入的其他文件。切换目录不会迁移或删除旧目录中的日志。占用与错误状态在设置页加载、保存时刷新；容量丢弃计数在网关重启后归零。

`GET/POST /api/admin/gateway-logs/config` 增加 `max_daily_size_mb`、`max_total_size_mb`。响应包含 `today_size_bytes`、`total_size_bytes`、`capacity_dropped_entries`、`cleanup_error`。POST 省略容量字段时保留已有值；旧配置和旧备份缺少字段时采用默认值。数值零不是“无限制”。

进程重启后创建新分片，避免把新记录追加到上次异常退出遗留的半条 JSON 后面。配置变更时请求线程不会等待磁盘清理；此时无法入队的记录计入丢弃数。日志查询等待写入锁时也遵守请求取消和超时。

分片游标是不透明字符串，客户端应原样回传。旧数字游标仅用于仍存在的旧格式文件。游标对应分片被清理后返回过期错误，刷新列表即可重新查询。

发布需同时包含本仓库和相邻 `Go-Reauth-Proxy` 仓库的修改。共享控制协议版本已提升至 25；`version.json` 的 `gatewayCommit` 已固定到包含该功能的本地 Go 提交。正式发布前需将 Go 提交推送到对应远端，再执行现有打包流程，不能搭配旧网关二进制发布。
